# Put Spread Weekly Screener — Full Build Prompt

Build a production-quality local web app called “Put Spread Weekly Screener” for ranking weekly put credit spread candidates.

This is a local-first trading research/screening dashboard. It is not a marketing landing page. The UI must be compact, practical, responsive, dashboard-like, and mobile-first.

Important: this app is for educational/research use only. Add a visible disclaimer that delayed market data may be inaccurate or unavailable and that the tool is not financial advice.

---

## 1. Core Product Goal

Build a local web application that lets me screen, rank, review, and track weekly put credit spread candidates.

The app should:

- Let me select a weekly option expiry.
- Pull delayed option-chain data.
- Pull earnings/event/macro data.
- Pull historical daily closes.
- Apply trend, volatility, liquidity, and risk gates.
- Rank candidate put credit spreads.
- Generate copyable order tickets.
- Let me track selected positions in localStorage.
- Alert me when tracked positions hit predefined risk/profit conditions.

## 6. Strategy Logic

Screen put credit spreads for the selected expiry.

For each symbol:

1. Fetch current underlying/option-chain data.
2. Fetch historical closes.
3. Fetch earnings data.
4. Fetch macro/event data if enabled.
5. Apply blocklist and event filters.
6. Generate candidate put credit spreads.
7. Apply liquidity, delta, width, credit, trend, and VIX gates.
8. Rank remaining candidates.
9. Return skipped symbols with clear reasons.

### Put Credit Spread Construction

For each candidate:

- Short leg must be a put.
- Long leg must be a lower-strike put.
- Spread width must be <= max spread width.
- Short delta must be between min/max short-put delta.
- Credit must be >= minimum credit as % of spread width.
- Open interest must meet minimum.
- Volume must meet minimum.
- Calculate:
  - net credit
  - max loss
  - breakeven
  - risk/reward
  - distance below spot
  - expected move
  - expected-move low
  - quote spread width
  - suggested contracts

Use conservative pricing:

- Prefer bid/ask-based realistic credit.
- Do not overstate credit by using only theoretical mid.
- Show both mid credit and conservative executable credit where possible.

## 7. Trend Validation

Trend validation should use:

- 20-day SMA
- 50-day SMA
- 5-day price change
- 20-day support
- RSI 14
- MACD 12/26/9 histogram

Create a trend status:

```ts
"strong" | "acceptable" | "weak" | "bearish" | "unknown"
```

A good candidate generally has:

- price above or near key moving averages
- positive or stable 5-day price action
- short strike below recent support
- RSI not severely overbought
- MACD histogram not materially weakening

Do not hard-fail everything if trend data is incomplete. Add warnings and lower ranking.

---

## 8. VIX Logic

Implement VIX regime logic:

- VIX < 15:
  - thin premium
  - reduce target delta
  - reduce size
  - add warning
- VIX 15–22:
  - normal
- VIX 22–30:
  - rich premium
  - reduce size
  - add caution warning
- VIX > 30:
  - avoid new weekly bullish spreads
  - strongly warn or block when VIX gate is enabled

Detect VIX trend from recent history:

```ts
"stable" | "rising" | "falling" | "unknown"
```

If VIX is rising, penalize bullish put spreads.

## 26. Important Implementation Notes

Be pragmatic.

If an external source is unavailable, blocked, or has changed response format:

- Do not fake live data.
- Add a clear warning.
- Keep the app functional.
- Use adapter boundaries so the data source can be fixed later.

Do not over-engineer with a database, authentication, cloud services, or a heavyweight backend framework.

Do not create a marketing site.

Do not make the UI flashy at the expense of usability.

Focus on correctness, maintainability, safety, and practical trading workflow.

At the end:

1. Start the local server.
2. Verify the page loads.
3. Verify JS and CSS load.
4. Verify `/api/health`.
5. Verify `/api/sources/status`.
